GitHub Actions CI/CD Pipeline

DevOps Case Study — Bishwajeet S  ·  workflow: .github/workflows/ci-cd.yml

Every push / PR

1. Test

  • Checkout repository
  • Python 3.11 + pip cache
  • flake8 lint
  • pytest unit tests
→
After Test passes

2. Build

  • Multi-stage Docker build
  • Tag: sha, branch, latest
  • Push to Docker Hub
  • Trivy CVE scan (shift-left)
→
Only branch: develop

3. Staging

  • Decode kubeconfig secret
  • kubectl apply -f k8s/
  • Wait for rollout status
→
Only branch: main

4. Production

  • kubectl set image (rolling)
  • maxUnavailable = 0
  • Health check pods + service
Notify job runs only if any prior job fails — it is not a success stage after production.
Staging and Production are parallel after Build and gated by branch, not a single linear path.
